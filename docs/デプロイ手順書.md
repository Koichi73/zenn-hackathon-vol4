# デプロイ手順書 (Cloud Run)

本ドキュメントは、バックエンドとフロントエンドの両方を **Cloud Run** にデプロイするための手順をまとめたものです。

## 変更履歴
- **2026-02-11**: フロントエンドのデプロイ先をFirebase HostingからCloud Runに変更
  - 理由: Next.jsの動的ルート（`/editor/[id]`など）を使用するため、静的エクスポートでは対応できない
  - メリット: SSR、動的ルート、API Routesなど、Next.jsの全機能が使用可能

## 0. 前提条件

以下のツールがインストール済みであること。
- Google Cloud CLI (`gcloud`)

## 1. Google Cloud プロジェクトの準備

ターミナルで以下を実行し、Google Cloudにログイン・プロジェクト設定を行います。

```bash
# ログイン（ブラウザが開きます）
gcloud auth login

# プロジェクトの作成（既存プロジェクトを使う場合はスキップ）
# project-id は世界で一意のものを指定してください
gcloud projects create [YOUR_PROJECT_ID] --name="Zenn Hackathon Vol4"

# プロジェクトの選択
gcloud config set project [YOUR_PROJECT_ID]

# 課金設定が有効になっているか確認してください（Cloud Runの使用に必須）
```

以下のAPIを有効化します。

```bash
gcloud services enable run.googleapis.com \
    artifactregistry.googleapis.com \
    cloudbuild.googleapis.com \
    firestore.googleapis.com
```

---

## 2. Artifact Registry の作成

Dockerイメージを格納するリポジトリを作成します（バックエンド・フロントエンド共通）。

```bash
gcloud artifacts repositories create backend-repo \
    --repository-format=docker \
    --location=asia-northeast1 \
    --description="Docker repository for backend and frontend"
```

---

## 3. バックエンド (Cloud Run) のデプロイ

### 3.1 ビルドとプッシュ

Cloud Build を使って、イメージをビルド・プッシュします。

```bash
cd backend

# イメージのビルドとプッシュ
gcloud builds submit --tag asia-northeast1-docker.pkg.dev/[YOUR_PROJECT_ID]/backend-repo/api-server:v1 .
```

### 3.2 Cloud Run へデプロイ

```bash
gcloud run deploy api-server \
    --image asia-northeast1-docker.pkg.dev/[YOUR_PROJECT_ID]/backend-repo/api-server:v1 \
    --platform managed \
    --region asia-northeast1 \
    --allow-unauthenticated \
    --set-env-vars GOOGLE_CLOUD_PROJECT=[YOUR_PROJECT_ID]
```

デプロイが成功すると、Service URL（例: `https://api-server-xxxxx.a.run.app`）が表示されます。**このURLをメモしておいてください。**

---

## 4. フロントエンド (Cloud Run) のデプロイ

### 4.1 フロントエンドのビルドとプッシュ

フロントエンドディレクトリで実行します。

```bash
cd ../frontend

# イメージのビルドとプッシュ
gcloud builds submit --tag asia-northeast1-docker.pkg.dev/[YOUR_PROJECT_ID]/backend-repo/frontend:v1 .
```

### 4.2 Cloud Run へデプロイ

```bash
gcloud run deploy frontend \
    --image asia-northeast1-docker.pkg.dev/[YOUR_PROJECT_ID]/backend-repo/frontend:v1 \
    --platform managed \
    --region asia-northeast1 \
    --allow-unauthenticated \
    --port 3000 \
    --set-env-vars NEXT_PUBLIC_API_BASE_URL=https://api-server-xxxxx.a.run.app
```

**注意**: `NEXT_PUBLIC_API_BASE_URL` には、手順3.2でメモしたバックエンドのURLを設定してください。

デプロイが成功すると、Service URL（例: `https://frontend-xxxxx.a.run.app`）が表示されます。**このURLがアプリケーションのURLになります。**

---

## 5. Firebase Authentication の設定

### 5.1 承認済みドメインの追加

Firebase Console（https://console.firebase.google.com/）にアクセスし、以下の手順で承認済みドメインを追加します。

1. プロジェクトを選択
2. **Authentication** → **Settings** → **Authorized domains** に移動
3. **Add domain** をクリック
4. Cloud Runのドメイン（`frontend-xxxxx.a.run.app`）を追加

これにより、Cloud RunのドメインからFirebase Authenticationが使用できるようになります。

## 6. 動作確認

Cloud Runのフロントエンド URL にアクセスします。

1. トップページが表示されるか。
2. ログイン等のAPIを叩く処理が正常に動くか。
   - ChromeのDevTools > Networkタブで、APIへのリクエストが `200 OK` になっているか確認。
   - Cloud Run のログでもリクエストが来ているか確認できます。

---

## 7. 権限設定（重要！）

Cloud Runのサービスアカウントに必要な権限を付与します。

```bash
# プロジェクト番号を取得
PROJECT_NUMBER=$(gcloud projects describe [YOUR_PROJECT_ID] --format="value(projectNumber)")

# Firestore 読み書き権限
gcloud projects add-iam-policy-binding [YOUR_PROJECT_ID] \
    --member=serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com \
    --role=roles/datastore.user

# Storage 読み書き権限
gcloud projects add-iam-policy-binding [YOUR_PROJECT_ID] \
    --member=serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com \
    --role=roles/storage.objectAdmin
```

---

## 8. カスタムドメインの設定（オプション）

独自ドメインを使用する場合は、Cloud Runのドメインマッピング機能を使用します。

```bash
# ドメインマッピングの作成
gcloud run domain-mappings create \
    --service frontend \
    --domain your-domain.com \
    --region asia-northeast1
```

その後、DNSレコードを設定してください（表示される指示に従います）。

## トラブルシューティング

### CORS エラーが発生する場合

フロントエンドの環境変数 `NEXT_PUBLIC_API_BASE_URL` が正しく設定されているか確認してください。

### 認証エラーが発生する場合

Firebase Consoleで、Cloud RunのドメインがAuthorized domainsに追加されているか確認してください。

### データベース接続エラーが発生する場合

サービスアカウントに適切な権限（Firestore、GCS）が付与されているか確認してください。
