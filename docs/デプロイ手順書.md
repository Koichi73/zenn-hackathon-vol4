# デプロイ手順書 (Cloud Run + Firebase Hosting)

本ドキュメントは、バックエンドを **Cloud Run**、フロントエンドを **Firebase Hosting** にデプロイするための手順をまとめたものです。

## 0. 前提条件

以下のツールがインストール済みであること。
- Google Cloud CLI (`gcloud`)
- Firebase CLI (`firebase`)

## 1. Google Cloud プロジェクトの準備

ターミナルで以下を実行し、Google Cloudにログイン・プロジェクト設定を行います。

```bash
# ログイン（ブラウザが開きます）
gcloud auth login

# プロジェクトの作成（既存プロジェクトを使う場合はスキップ）
# project-id は世界で一意のものを指定してください
gcloud projects create [YOUR_PROJECT_ID] --name="Zenn Hackathon Vol4"

# プロジェクトの選択
gcloud config set project [YOUR_PROJECT_ID]

# 課金設定が有効になっているか確認してください（Cloud Runの使用に必須）
```

以下のAPIを有効化します。

```bash
gcloud services enable run.googleapis.com \
    artifactregistry.googleapis.com \
    cloudbuild.googleapis.com \
    firestore.googleapis.com
```

---

## 2. バックエンド (Cloud Run) のデプロイ

### 2.1 Artifact Registry の作成

Dockerイメージを格納するリポジトリを作成します。

```bash
gcloud artifacts repositories create backend-repo \
    --repository-format=docker \
    --location=asia-northeast1 \
    --description="Backend Docker repository"
```

### 2.2 ビルドとプッシュ

Cloud Build を使って、イメージをビルド・プッシュします。
※ `backend` ディレクトリで行います。

```bash
cd backend

# イメージのビルドとプッシュ
# PROJECT_ID はご自身のプロジェクトIDに置き換えてください
gcloud builds submit --tag asia-northeast1-docker.pkg.dev/[YOUR_PROJECT_ID]/backend-repo/api-server:v1 .
```

### 2.3 Cloud Run へデプロイ

```bash
gcloud run deploy api-server \
    --image asia-northeast1-docker.pkg.dev/[YOUR_PROJECT_ID]/backend-repo/api-server:v1 \
    --platform managed \
    --region asia-northeast1 \
    --allow-unauthenticated \
    --set-env-vars GOOGLE_CLOUD_PROJECT=[YOUR_PROJECT_ID]
```

デプロイが成功すると、Service URL（例: `https://api-server-xxxxx.a.run.app`）が表示されます。**このURLをメモしておいてください。**

## 3. フロントエンド (Firebase Hosting) のデプロイ

### 3.1 Firebase プロジェクトの初期化

プロジェクトルートで実行します。

```bash
cd .. # プロジェクトルートに戻る
firebase login
firebase init hosting
```

質問には以下のように答えます：
- **Project Setup**: `Use an existing project` -> 先ほど設定したGoogle Cloudプロジェクトを選択
- **Public directory**: `.next` ではなく、後述の設定ファイルで制御するため一旦デフォルト(`public`)のままでOK（後で上書きします）
- **Configure as a single-page app**: `No` (Next.jsのため)
- **Set up automatic builds and deploys with GitHub**: `No` (今回は手動デプロイ)

### 3.2 設定ファイルの作成・修正

プロジェクトルートにある `firebase.json` を以下のように編集します。
これにより、`/api/` へのアクセスが自動的に Cloud Run へ転送されます。

**firebase.json**
```json
{
  "hosting": {
    "public": "frontend/out",
    "ignore": [
      "firebase.json",
      "**/.*",
      "**/node_modules/**"
    ],
    "rewrites": [
      {
        "source": "/api/**",
        "run": {
          "serviceId": "api-server",
          "region": "asia-northeast1"
        }
      }
    ],
    "cleanUrls": true
  }
}
```

### 3.3 フロントエンドのビルド設定

`frontend/next.config.mjs` を確認し、静的エクスポート設定になっているか確認します。
（`output: 'export'` が必要ですが、API RouteをRewriteでCloud Runに流す構成の場合、画像最適化などに制約が出ることがあるため注意が必要です。今回はCloud Runとの併用なので、SPAとしてビルドしHostingに置く形になります）

**環境変数の設定 (.env.production)**
フロントエンドからバックエンドへのリクエストは、Rewrite機能により同一ドメインとして扱えるため、ベースURLは空（または `/api` 始まり）でOKになります。

```bash
# frontend/.env.production
NEXT_PUBLIC_API_BASE_URL="" 
# ↑ もしくは、ローカル開発と合わせるために明記する必要があれば HostingのURL を指定
```

### 3.4 ビルドとデプロイ

```bash
cd frontend
npm run build
# output: 'export' の場合、out ディレクトリが生成されます

cd ..
firebase deploy --only hosting
```

## 4. 動作確認

`firebase deploy` コマンド完了後に表示される **Hosting URL** にアクセスします。

1.  トップページが表示されるか。
2.  ログイン等のAPIを叩く処理が正常に動くか。
    - ChromeのDevTools > Networkタブで、`/api/xxxx` へのリクエストが `200 OK` になっているか確認。
    - Cloud Run のログでもリクエストが来ているか確認できます。

## 5. よくあるエラーと対策 (CORS, DB, Auth)

デプロイ時にハマりやすいポイントとその対策です。

### 5.1 CORS (Cross-Origin Resource Sharing)
**心配不要です。**
今回の `firebase.json` の `rewrites` 設定により、フロントエンドとバックエンドは「同じドメイン」として振る舞います。
- ブラウザ: `https://your-app.web.app/api/analyze` にアクセス
- Firebase: 内部で `api-server` (Cloud Run) に転送
ブラウザからは同一オリジンに見えるため、CORSエラーは原理的に発生しません。

### 5.2 DB・Storage接続 (Firestore / GCS)
Cloud Run は「デフォルトのサービスアカウント」で動作しますが、これに権限がないとエラーになります。
以下のコマンドで、Cloud Runのサービスアカウントに権限を付与してください（初回のみ）。

```bash
# プロジェクト番号を取得
PROJECT_NUMBER=$(gcloud projects describe [YOUR_PROJECT_ID] --format="value(projectNumber)")

# Firestore 読み書き権限
gcloud projects add-iam-policy-binding [YOUR_PROJECT_ID] \
    --member=serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com \
    --role=roles/datastore.user

# Storage 読み書き権限
gcloud projects add-iam-policy-binding [YOUR_PROJECT_ID] \
    --member=serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com \
    --role=roles/storage.objectAdmin
```
また、コード内では `google.auth.default()` や `firestore.Client()` を引数なしで呼ぶことで、自動的にこの認証情報が使われます（キーファイル不要）。

### 5.3 ログイン (Firebase Authentication)
Firebase Hosting で発行されるドメイン（`xxx.web.app`）は、**自動的にFirebase Authの承認済みドメインに追加**されます。
そのため、追加設定なしで Google ログイン等が動作します。
もしカスタムドメインを使う場合は、Firebase Consoleの `Authentication > Settings > Authorized domains` に追加する必要があります。
