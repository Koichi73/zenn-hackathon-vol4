# コメント既読管理機能 設計書

## 1. 概要
ユーザーごとにマニュアル内のコメントの既読・未読状態を管理し、ダッシュボード等で未読数をバッジ表示する機能。

## 2. データ構造（Firestore）

### A. 既読ステータス管理
ユーザーごとの既読時刻を記録する。
- **コレクション**: `comment_read_status`
- **ドキュメントID**: `{user_id}`
- **構造**:
  ```json
  {
    "manuals": {
      "{manual_id}": {
        "last_read_at": timestamp // 最後にそのマニュアルを閲覧した時刻
      }
    }
  }
  ```

### B. マニュアルメタデータの拡張
高速な未読判定のためにマニュアル側に最新コメント時刻を保持する。
- **コレクション**: `users/${user_id}/manuals`
- **追加フィールド**:
  - `last_comment_at`: timestamp // そのマニュアルに最後にコメントが投稿された時刻

### C. コメントデータの拡張
一括取得（コレクショングループクエリ）を可能にするため、サブコレクション内のドキュメントに親IDを保持する。
- **パス**: `comments/{manualId}/steps/{stepIndex}/comments/{commentId}`
- **追加フィールド**:
  - `manual_id`: string // フィルタリング用
  - `step_index`: number // 表示位置特定用

---

## 3. 主要ロジック

### ① 既読マーク処理
- **トリガー**: ユーザーがエディターまたはプレビュー画面で特定のマニュアルを開いた時。
- **処理**: `comment_read_status/{userId}` の対象 `manual_id` の `last_read_at` を現在のサーバー時刻で更新する。

### ② コメント投稿処理
1. コメントをサブコレクションに保存（この際、`manual_id` を付与）。
2. 対象マニュアルドキュメントの `last_comment_at` を現在のサーバー時刻で更新する。
   - ※「自分の投稿も未読とする」仕様のため、投稿者本人の `last_read_at` は更新しない。

### ③ 未読数計算ロジック（高速化戦略）
バックエンドで以下の2段階判定を行う。
1. **最終投稿時刻チェック**:
   - `last_read_at（既読時刻）` >= `last_comment_at（最新コメント時刻）` であれば、未読なし（0）として即座に返す。
2. **コメント全チェック**:
   - 上記以外（またはデータ不足）の場合、コレクショングループクエリで対象マニュアルの全コメントを取得。
   - `created_at` > `last_read_at` となるコメントの数を算出して返す。

## 4. API定義

| エンドポイント | メソッド | 説明 |
| :--- | :--- | :--- |
| `/api/comments/manuals/unread-counts` | `POST` | 指定した複数マニュアルの未読数を一括取得（ダッシュボード用） |
| `/api/comments/manuals/{id}/unread-count` | `GET` | 特定マニュアルの未読数を取得 |
| `/api/comments/manuals/{id}/mark-read` | `POST` | 指定マニュアルを既読としてマーク |

---

## 5. パフォーマンス最適化
- **コレクショングループインデックス**: `comments` コレクションの `manual_id` フィールドにインデックスを貼り、全ステップのコメントを1クエリで取得可能に。
- **非同期並列実行**: ダッシュボードでの一括取得時、`asyncio.gather` により各マニュアルの計算を並列化。
- **キャッシュ戦略**: ブラウザ側で `no-store` を指定し、常に最新の未読状態を反映。
